# docs/

Written deliverables and the records the rubric asks for.

| File | Purpose | Owner |
|---|---|---|
| `data_card.md` | Corpus audit: source/version, license/terms, encoding, split usage, slice rule, count, checksum, character-category statistics. | Samrat |
| `tokenizer_card.md` | Tokenizer configuration: library versions, checkpoint + revision, casing/normalization, special tokens + IDs, vocab size/source/checksum, max length, plus the BPE-vs-WordPiece paragraph. | Prazol |
| `contribution_record.md` | Who did what, and the shared integration decisions. | both |
| `report_outline.md` | Skeleton of the 3-5 page technical report, section by section. | both |
| `acceptance_checklist.md` | The signed acceptance checklist. | both |
| `assignment/` | Original assignment PDFs, plus `Phase-1/PHASE1_PLAN.md` (the team's plan for this phase). | — |

The final technical report PDF is built from `report_outline.md` (write it in your editor of
choice; keep the outline in sync).
